A camada visual vira Tailwind e shadcn

branchmain planodocs/plans/2026-08-22-camada-visual-shadcn.md a fundação fica intacta shared/ui sai inteiro

O boilerplate nasceu com 15 componentes próprios e 24 folhas de estilo. Eles servem, e custaram caro. Mas todo projeto novo quer Tailwind e shadcn, e reescrever a casca a cada vez desperdiça a fundação que está embaixo dela. Esta spec troca a casca e prova que a fundação sobrevive.

Resumo

O shared/ui sai inteiro: 15 componentes, 24 folhas de estilo, 32 exportações. Entra o shadcn, com Tailwind v4 pelo plugin do Vite.

A fundação não é tocada. O entities/, o shared/api, o shared/lib e o shared/config têm zero import de CSS hoje. Isso foi medido, não suposto. São 94 testes que continuam válidos sem alteração.

A tela /pessoas é reescrita e continua verde. Ela é a prova de que a fundação sobrevive à troca de interface.

01 Problema

O shared/ui do boilerplate tem 15 componentes escritos à mão, com 1.457 linhas de TypeScript e 1.608 de CSS. Eles têm teste, respeitam token e resolvem acessibilidade. Não são ruins.

O problema é outro: eles são uma opinião visual que todo projeto novo herda sem escolher. Quem começa uma tela quer npx shadcn add e seguir. Em vez disso encontra um sistema próprio, com nomes próprios, que precisa aprender antes de escrever a primeira linha.

O que a medição mostrou

A separação entre negócio e interface é real neste repositório. O entities/, o shared/api, o shared/lib e o shared/config somam zero import de CSS. O features/ tem dois. Só o pages/ concentra o acoplamento, com vinte.

Isso não é promessa de arquitetura. É o que o grep devolve hoje, e é o que torna esta troca viável.

02 Escopo

Dentro

  • Instalar Tailwind v4 pelo @tailwindcss/vite, e inicializar o shadcn.
  • Remover os 15 componentes de shared/ui e as 24 folhas de estilo de módulo.
  • Traduzir os quatro arquivos de estilo global para o bloco @theme.
  • Reescrever o shell, a tela de entrada e a tela de pessoas com shadcn.
  • Apontar o verifica-tokens.mjs para o @theme.
  • Reescrever a página /design-system como catálogo do que o shadcn traz.
  • Atualizar o README, o CLAUDE.md e o CONTRIBUTING.md.

Fora

  • Alterar entities/, shared/api, shared/lib ou shared/config. Eles não conhecem interface.
  • Alterar o contrato, o cliente HTTP, a sessão ou a permissão.
  • Alterar a ordem das camadas ou o eslint.config.js que a impõe.
  • Trocar o @tanstack/react-table. O shadcn usa o mesmo.
  • Criar branch. O trabalho acontece na main.

03 Solução

A troca acontece de baixo para cima: primeiro a base de estilo, depois os componentes, depois as telas que os consomem. Cada etapa mantém a bateria verde.

3.1 O que passa intacto

Nenhum destes arquivos importa CSS. A troca não os alcança.

Por que o cn sobrevive

O shared/lib/cn.ts já faz o que o shadcn espera do cn() dele: juntar classe condicional. O shadcn instala o próprio em lib/utils. Os dois fazem a mesma coisa, e manter dois seria confusão — o que existe fica, e o do shadcn é apontado para ele.

3.2 O que sai

Quinze componentes, 1.457 linhas de TypeScript. Vinte e quatro folhas de estilo de módulo, 1.608 linhas. Os 32 testes que cobrem só a casca saem junto: o shadcn traz os dele.

Saem também os cinco pacotes @radix-ui/react-* instalados hoje. O shadcn passou a usar o pacote unificado radix-ui, e manter os dois duplicaria a árvore de dependência.

3.3 A tradução dos tokens

O tokens.css tem 283 linhas em duas variantes, claro e escuro. Ele vira o bloco @theme do Tailwind v4, que é onde a v4 declara tema — não existe mais tailwind.config por padrão.

HojeDepoisObservação

Uma troca que altera comportamento

O tema hoje é o atributo data-theme, escrito pelo TemaProvider e lido em sete arquivos. O shadcn espera a classe .dark no elemento raiz.

O provedor passa a escrever a classe. O atributo sai. Quem depende dele — o teste do shell e a página de design system — acompanha.

O custo do Phosphor

O pacote exporta mais de nove mil módulos, e alguns empacotadores transpilam todos. O sintoma é compilação lenta em desenvolvimento, não artefato maior.

O contorno é importar pelo caminho direto do ícone, e não pela raiz do pacote: @phosphor-icons/react/dist/csr/House. O peso e o tamanho padrão ficam num IconContext.Provider só, no provedor raiz.

A marca é o único que fica

Ela carrega o marcador Fotus Default que o New-Project.ps1 substitui na geração. Trocá-la por componente de biblioteca quebraria o ritual de geração. Ela permanece, reescrita em classe utilitária.

08 Critérios de aceite

No boilerplate

  • npm ci termina com código 0.
  • npm run lint passa, incluindo o verificador de tokens reapontado.
  • npm run typecheck passa nos três tsconfig.
  • npm test passa, e a fatia pessoa continua com teste próprio.
  • npm run api:check confirma que o contrato e o schema batem.
  • npm run build gera o artefato.
  • npm run e2e passa nos três specs, inclusive o de ordem de pintura.
  • Nenhum arquivo .module.css sobra em src/.
  • Nenhum pacote @radix-ui/react-* individual sobra no package.json.
  • O tema claro e o escuro funcionam, e a paleta Fotus permanece.

No projeto gerado

  • O script cria o destino e recusa destino que já existe.
  • Nenhum arquivo carrega BOM.
  • Nenhuma ocorrência de fotus-default-web nem de Fotus Default sobra.
  • A bateria inteira do critério anterior passa dentro do destino.
